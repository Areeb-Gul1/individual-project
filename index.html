Explainable AI with CNNs — Grad-CAM on PlantVillage

A short, story-based tutorial showing how we train a CNN classifier and then use Grad-CAM to visualise what parts of a leaf image most influenced the prediction (Selvaraju et al., 2017).

The idea in plain language

Imagine an AI is asked to identify plant disease from a photo. The model can be accurate, but it may be hard to trust. Grad-CAM (Selvaraju et al., 2017) turns the decision into a heatmap so you can see which image regions were most influential for the predicted class.

Important: Grad-CAM is a post-hoc visual explanation. It highlights correlated evidence used by the model, but it does not prove the highlighted pixels are the true biological cause of disease (Ribeiro et al., 2016).

1) Scene A — The photos (PlantVillage dataset)

The dataset comes from PlantVillage (Hughes & Salathé, 2015). In this project we select a small set of “healthy” and “disease” classes to keep the tutorial fast and focused.

2) Scene B — Training the learner

We split images into training, validation, and test sets so we can measure how well the model learns and how well it performs on unseen images. (Validation is a better indicator than training accuracy alone.)

3) Scene C — The report card (learning curves)

We track two signals: (1) loss (lower is better), and (2) accuracy (higher is better) on training vs validation.

4) Scene D — Evaluation (where predictions go wrong)

A confusion matrix shows which classes the model confuses. Diagonal entries represent correct predictions.

5) Scene E — The explanation (Grad-CAM heatmaps)

Each snapshot shows: (1) the original photo, (2) a heatmap (brighter = stronger influence), (3) an overlay that helps non-technical readers understand where the model “looked”.

Ethics note (what Grad-CAM can and cannot promise)

Grad-CAM provides post-hoc explanations, but these are not causal and may highlight correlated features rather than true disease regions (Ribeiro et al., 2016).

Additionally, models trained on PlantVillage may not generalise well to real-world conditions due to controlled backgrounds, lighting, and image quality. This can lead to biased predictions if deployed in practical agricultural settings.

Therefore, such systems should be used as decision-support tools rather than fully automated solutions, and predictions should be validated by domain experts before taking action.
